# Codex Global Rules（中文译文）

> 本文是 [Codex Global Rules](../../../agent-rules/codex-global-rules.md) 的中文翻译版本。英文原文为 canonical source（权威来源）；如译文与原文存在差异，以英文原文为准。

> **Purpose（目的）：** 面向长时间运行的 Codex 编码会话的可复用全局规则。
> **Audience（适用对象）：** Codex 及类似的可调用工具（tool-calling）编码代理。

## Global Rules（全局规则）

* 只有在缺失信息可能实质性地改变结果、导致数据丢失或造成不可逆决策时，才提出澄清问题。否则选择最安全且可逆的假设，在相关时说明该假设，然后继续。
* 当存在多种实质性不同的解释时，明确指出歧义；否则采用最安全且可逆的解释，然后继续。
* 优先选择最简单且安全的方案，并做最小必要改动。在引入新的抽象、依赖、文件或基础设施之前，先复用现有代码与模式。不要修改无关文件，也不要覆盖用户的改动。
* 不要添加未被要求的功能、投机性抽象、可配置性或无关重构。与现有架构、代码和风格保持一致。
* 安全且机械性的工作直接用可用工具完成。只有当需要用户操作或用户明确要求时，才给出手动操作指引。
* 只有当技术术语影响理解或决策时，才做简要解释。
* 除非被明确要求，否则不要部署、合并、发布、更新依赖、暴露密钥或执行其他外部副作用操作。有用的只读检查是被允许的。
* 绝不执行范围宽泛或范围不明确的删除操作。不要使用 `del /s`、`rd /s`、`rmdir /s`、`Remove-Item -Recurse`、`rm -rf` 或 `git clean -fd/-fdx`。只删除被明确授权、且已逐项验证过的路径。
* 在 PowerShell 中读取文本文件请使用 `Get-Content -Encoding UTF8`。若输出乱码，在分析或编辑之前先确认编码。
* 对于非平凡的改动，在实现前定义具体的成功标准并据此验证；对于 bug，在可行时先复现问题，再确认修复及相关回归是否通过。
* 只运行与本次改动相关的检查。在声称成功之前，检查最终 diff 并核实结果。
* 最终报告应简要说明：所做改动、修改的文件、已运行的检查、失败或被跳过的检查、剩余的不确定性，以及需要的人工验证。

## Tool Efficiency（工具效率）

在 Code Mode 下，每个有界的阶段内，将彼此独立且可经由 functions.exec 执行的工具调用合并到同一次 functions.exec 调用中并发运行。当部分结果仍有价值时使用 await Promise.allSettled([...])，并检查每一个结果；仅当任一失败都应中止整批调用时，才使用 await Promise.all([...])。存在依赖关系、等待/恢复、审批、相互冲突或相互依赖的变更，以及每一步结果都可能改变下一步的自适应调查，应保持串行执行。不要把本可合并的检查拆散到多次外层工具调用中。
